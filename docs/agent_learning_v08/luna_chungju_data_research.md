# Agent Learning Note

## Role

Subagent C / LUNA — LightGuard v0.8 Chungju Asset Data Recovery Research

## Model actually used

LUNA

## Scope and invariant

대상은 충주시 공개 가로등 분전함 871개다. 조사 목표는 공개 분전함 키가 램프 종류, 정격 W, 안정기·LED 정격, 분전함 회로 용량, 회로별 실측부하, AMI/계량기 매핑으로 이어지는지 확인하는 것이다.

다음은 조사·문서화 과정에서 금지했다.

- 수영구·강릉의 평균 정격을 충주에 전이
- 등주수량에 임의 W를 곱해 정격부하 생성
- 조달 공고의 `LED 150W 이하` 또는 `컨버터 80/60W`를 충주 전체의 자산 사실로 해석
- 제조사 카탈로그 사양을 실제 설치 자산 사양으로 주장
- 주소·좌표의 근접성만으로 분전함·등기구·AMI를 추정 매칭

## Evidence synthesis

현재 871개 전체에 대해 `RECOVERABLE_OFFICIAL`인 것은 공개 분전함 식별·위치·등주수량 메타데이터뿐이다. 램프 종류, W, 안정기/컨버터, 분전함 회로수는 공식 조달·설계·준공 자료에서 일부 사업 단위로 회수될 가능성이 있어 `PARTIALLY_RECOVERABLE`로 분류한다. 회로별 정격부하와 AMI/계량기 매핑은 현재 공개자료로 연결되지 않아 `NOT_RECOVERABLE`이다.

조달 문서가 제공하는 `LED150W 이하`, `80/60W`, `4회로`는 복원 후보 필드와 자료 요청 명세를 구체화하는 데 유용하지만, 자산 진실값이 아니다. 최종 데이터 행은 다음 증거 체인을 모두 가져야 한다.

```text
충주 분전함 번호
-> 계약/설계/준공 문서번호
-> 위치별 대상 목록
-> 등기구 또는 회로 식별자
-> 정격·부하 값
-> 기준일·검증자·원문 페이지
```

하나라도 끊기면 해당 행은 미복원 상태로 남긴다.

## Risks

- 공개 파일의 연간 갱신으로 분전함 번호·위치·등주수량이 변경될 수 있다.
- 조달 계약의 규격은 시공 시점·공사 대상에 한정되며 전체 자산의 현행 사양을 대표하지 않을 수 있다.
- 설계도서, 회로도, 계량기 번호는 시설보안·계약·개인정보 또는 전력공급자 정책으로 부분 비공개될 수 있다.
- 준공자료가 종이 문서 또는 부서 내부 시스템에만 있으면 기계적 871행 조인이 불가능할 수 있다.
- 전기안전 점검 주기와 실제 측정 시점이 다르면 정격부하와 운영부하를 혼동할 수 있다.
- 충주 실제 AMI가 없으므로 데이터 복원 전후에도 현장 탐지 일반화 주장은 할 수 없다.

## Adopted rules

1. `분전함 번호`만 공식 1차 키로 사용하고, 주소·좌표 근접성은 후보 검색용으로만 사용한다.
2. 등주수량을 와트로 변환하지 않는다.
3. 다른 지역 평균·제조사 카탈로그·계약 상한값을 충주 자산값으로 대체하지 않는다.
4. 계약 문서의 규격은 위치별 대상과 준공 증거가 있을 때만 해당 행에 연결한다.
5. `0W`와 `미확보`를 구분하고 앱에서는 `unavailable_no_imputation`을 유지한다.
6. 회로부하는 분전함별 회로도·차단기 정격·측정 시점·전력계량/AMI 증거가 모두 있을 때만 `RECOVERABLE_OFFICIAL`로 승격한다.
7. 정보공개 또는 공공데이터 제공 신청의 결과가 오기 전에는 데이터셋·앱·스크립트를 변경하지 않는다.
8. 조사 산출물은 `lightguard_app/docs/chungju_load_data_recovery.md`와 본 학습노트에만 기록한다.
