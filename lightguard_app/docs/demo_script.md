# LightGuard Demo Script (3~5분)

## 1. 문제와 아이디어 (30초)

기존 관제는 점등 명령을 보냈다는 상태를 알 수 있지만 실제 전력이 기대대로 흐르는지는
별도 확인이 필요합니다. LightGuard는 기존 시스템을 교체하지 않고 AMI를 독립 검증
레이어로 추가합니다.

핵심 메시지: 새 센서를 대규모로 설치하는 대신 이미 존재하는 AMI를 실제 전력 상태를
확인하는 독립 검증 레이어로 재활용합니다.

## 2. Dashboard와 수영구 실제 자산 (40초)

- 실제 공공자산 분전함 204개, 실제 등 수 4,239등, 정격용량 약 488.44 kW를 확인합니다.
- 실제 공공자산 204, controlled scenario 46, 공모전 AMI 후보 6, 실제 지자체 AMI 연결 0을 구분해 설명합니다.

## 3. 지도와 Scenario 점검 후보 (40초)

- 지도에서 수영구 분전함 마커 204개가 렌더링되는지 확인합니다.
- 점검 우선순위에서 `Source: 검증 시나리오` 필터와 activation, duration, expected load, reason을 확인합니다.
- 46/46은 사전 정의한 scenario 재현 검출이며 현장 정확도 100%가 아님을 말합니다.

## 4. 분전함 상세 근거 (35초)

- 자산 정보 → 예상 운전 → 최대 activation 요약 → 이상 근거 → 점검 우선순위를 순서대로 봅니다.
- activation 막대는 원시 시계열이 아니라 보유한 이벤트 summary임을 강조합니다.

## 5. 실제 공모전 AMI Case Study (60초)

- 전체 점검 후보 6건과 초과전력량 합계 3.994 kWh를 확인합니다.
- B-L-35의 OFF 0.05A / Peak 16.55A / ON 17.16A를 비교합니다.
- B-L-9의 강한 주간 활성, B-L-14의 특정 상 중심 활성 사례를 확인합니다.
- 모두 가명화 공모전 AMI에서 탐지한 현장 미확인 점검 후보임을 설명합니다.

## 6. 지역 확장과 저비용 구조 (40초)

- 강릉: Controller-linked Validation, 실제 AMI 연결 없음
- 충주: Minimal Asset / Asset-only, 실제 AMI 연결 없음
- 기존 인프라 재활용, 추가 현장 센서 최소화 가능성, 점검 대상 우선순위화가 사업화 가설입니다.

## 7. 제한사항과 다음 단계 (25초)

- 실제 지자체 AMI meter ↔ 분전함 매핑, 정비이력, 고장 label이 아직 없습니다.
- 다음 단계는 실제 pilot에서 ID 매핑과 정비이력을 연결해 현장 성능을 산정하는 것입니다.
